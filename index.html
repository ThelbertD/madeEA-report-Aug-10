Two decisions worth explaining

Why the guards hold instead of softening

When a draft breaks an SOP rule, the obvious move is to rewrite it and send the fixed version. The setter does not do that. A draft that trips a guard is held for a human and nothing is sent.

The reason is that the guards catch the failures where a plausible repair is more dangerous than silence. If the model quotes a price that isn't in the Fact Pack, the problem isn't the wording — it's that it invented a commercial term. Auto-correcting that to an approved number would send a confident message built on a reasoning error nobody ever sees. Holding it surfaces the error instead.

The cost is a queue of held conversations that need a person. That queue is visible as a tag, and its size is the honest measure of how well the prompt is tuned. A guard firing constantly means the SOP text needs work — not that the guard needs loosening.

Why the follow-up ladder stops at one rung

The SOP specifies four touches: 24 hours, 3 days, 7 days, then gone cold. Only the first is built, and that is a platform limit rather than an omission.

Instagram will not deliver a message more than 24 hours after the lead's last one. The other three touches fall entirely outside that window — they cannot be sent on this channel at any cadence. The nudge fires at roughly 20 hours because that is the latest point that still honours the SOP's timing and remains deliverable.

Extending the ladder means changing channel — email, or a paid message tag. Until then the live sequence is: reply, one nudge, close the loop. Everything past that is manual, and worth knowing rather than discovering.

Work completed

Workflows

  • DM setter re-contexted onto MadeEA — 15 nodes on a 2-minute trigger. Qualifies inbound Instagram DMs, drafts a reply against the SOP, checks it, and sends at most two bubbles four seconds apart.
  • Day-1 follow-up re-contexted — 20 nodes on a 30-minute trigger. Chases leads who went quiet using the follow-up rung matching whichever phase the conversation stalled in.
  • The SOP became the brain — five phases, Fact Pack, three walls, objection scripts and the follow-up ladder now live in the cached system prompt rather than scattered through node logic.
  • Seven safety guards — blocks VA/outsourcing/offshore wording, any price outside the Fact Pack, anything over two sentences, bracket placeholders, AI-identity claims, false promises, and freebie-chasers arriving from other funnels.
  • Wall classification — every lead is tagged capacity, trust or burned-before, so whoever takes the call knows which bridge landed.
  • Namespaced tagging — all lifecycle tags scoped to madeea-setter-* so they cannot trip an existing automation in the account.

Corrections to the inherited workflows

  • Fixed a live bug — the follow-up's elapsed-time value was wrapped in mismatched quote styles, so it was never evaluated. The model was being handed raw source text instead of how long the lead had been quiet, and the helper that computed it was dead code.
  • Stripped two plaintext secrets — an Anthropic API key and a GoHighLevel token were hardcoded in the source files. Both replaced with credentials and placeholders.
  • Removed the foreign instance fingerprint — the files carried the originating n8n instance's id, which blocked a clean import.
  • Normalised the file shape — stripped to the five keys n8n reads, LF line endings, no BOM, ASCII names.

Documentation and cleanup

  • Three documents — what the setter does and why each guard exists; a deploy guide covering hosting, credentials and the dry run; and build prompts for rebuilding it from scratch.
  • A shareable preview page for the team, showing the flow, the phases and the guardrails with real blocked-versus-sent examples.
  • Removed an abandoned approach — an earlier Supabase-based build (migration, two edge functions, unused types) deleted after it caused two mis-imports and would have created dead tables on the next database push.
